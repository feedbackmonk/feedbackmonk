# `aria-status` Oracle

## Synopsis

Project-state oracle reporting ARIA instrumentation health (surface present, endpoint reachable, foundation-layer status) and emitting the `[aria-status]` ORACLE BRIEFING line — **Leg A** of ARIA's four-leg detection machinery (DEC-26, ARIA-03), the predictive session-start surface. Come here for endpoint-probe semantics (300ms hard ceiling), the five briefing-line forms, the surface-present rule, and the optional `.claude/aria.json` config schema. Don't come here for the surface-classification logic itself — that delegates to the sibling `ui-surface-detector` (ARIA-02, Leg B).

## Purpose

Answers *"What is the ARIA instrumentation status of this project?"* — surface present? endpoints reachable? foundation-layer healthy? — and emits a single-line briefing for the session-start ORACLE BRIEFING block.

This oracle is **Leg A** of ARIA's four-leg detection machinery (Phase 1 per DEC-26, ARIA-03). Sibling: `ui-surface-detector` (ARIA-02), which this oracle uses for surface detection.

Spec: ARIA-01, ARIA-03 in `docs/specs/SPECIFICATION.md`. Contract: ARIA-07.

## AOR `capabilities` field (ARIA-17)

`capabilities` (optional) is the **AOR capabilities disk companion** — the static, value-free projection of an AOR-conformant app's runtime manifest (`AOR_CONTRACTS.md` §4, the Agent-Operable Runtime / ARIA Phase 4 surface). When the project commits `.claude/aria-manifest.json`, this oracle reads it and emits it verbatim under `capabilities`, so an agent learns the surface shape (which verbs, which introspect slices, which actuate commands with their `reversible`/`affects` hints, which observables) **before the app is even running**.

- **Source of truth** is the running adapter's `manifest()` / `GET /aor/capabilities`; the disk file is its committed projection (regenerated by the app's `verify:aor`). A consumer that has both prefers the runtime manifest.
- **NO-DATA semantics** (DISC-ARIA-09 lineage): absent or malformed `.claude/aria-manifest.json` → the field is **omitted**, never an empty-capabilities claim. The companion is read only when the surface is present; a production build that strips the AOR surface still ships no manifest, so the field is correctly absent.
- Validated for integrity: when present it must carry a `verbs` key (validators reject an empty-capabilities claim).
- First emitted by SessionHelm (ARIA-19) and Table (ARIA-23). Spec: ARIA-17.

## Operability Ladder fields (OPER-05, DEC-133)

`operability_tier` and `switchboard` (both optional, additive) are top-level convenience projections of the capabilities companion's optional `operabilityTier` / `switchboard` fields (`AOR_CONTRACTS.md` Appendix A — the Agentic Testing System's per-app conformance ladder):

- `operability_tier` ∈ `"T0" | "T1" | "T2" | "T3"` — the app's declared tier (T0 discoverable / T1 operable / T2 controllable / T3 simulable).
- `switchboard` — the reserved `aor.*` Test-Mode Switchboard families the app implements (e.g. `["aor.clock", "aor.seed", "aor.state.seed"]`).
- Emitted only when `capabilities` is present AND declares them; **NO-DATA otherwise** — the oracle never infers a tier and never defaults to `"T0"` (an undeclared app is *undeclared*, not tier-zero).
- Consumers: the Agent-Testability Gate Q6 (OPER-04, `segments/-ldis/plan-phase4-testability-gate.md`) and `/0-uldf-verify-fast`'s AOR consultation. Spec: § OPER in `docs/specs/SPECIFICATION.md`.

## Briefing-Line Forms (ARIA-01 acceptance #5)

| Case | Briefing |
|------|----------|
| present-and-healthy | `ARIA: errors+async+navigation healthy (qph=N)` |
| present-but-degraded | `ARIA: <healthy cats> healthy; <degraded cats> UNREACHABLE — see /0-uldf-oracle aria-status` |
| instrumented-but-unreachable (`.claude/aria.json` exists, server down) | `ARIA: configured but endpoint unreachable at <url>` |
| surface-but-no-instrumentation (no `.claude/aria.json`, server down) | `ARIA: UI/runtime surface detected; no ARIA instrumentation. /0-uldf-ldis-plan can scaffold.` |
| no-surface | empty string (line suppressed by hook) |

`qph` (queries per hour) = `query_count_24h / 24`, computed from `.claude/aria-telemetry.jsonl`. When `telemetry_state` is `no-data`, the healthy briefing reads `(qph=no-data; telemetry meter not armed, see ARIA-13)` — NO-DATA is never presented as `qph=0` (DISC-ARIA-09).

Briefing is always ≤200 chars (defensively truncated).

## Surface-Present Rule

The oracle delegates to `ui-surface-detector`. `surface_present: true` when `surface_kind ∉ {none, cli-tool}`. CLI tools may eventually expose ARIA-style instrumentation, but the foundation-layer endpoints (errors, async, navigation) target UI/service runtime perception per DEC-26.

## Endpoint Probe

- Default endpoint: `http://127.0.0.1:14550/aria/health` (per ARIA-07 contract). Override via `.claude/aria.json` `endpoint_url` field.
- Probe timeout: **300ms hard ceiling**. On timeout → `endpoint_reachable: false`.
- Response validation: must include `_meta` envelope + `oracleStatus`. Schema-violating responses are treated as unreachable.
- Foundation-layer derivation:
  - `oracleStatus: "healthy"` → all three categories `true`
  - `oracleStatus: "degraded"` → `_meta.degradedCategories[]` flips matching booleans to `false`; rest remain `true`
  - Server unreachable → all three `false`

## Telemetry (ARIA-13 capture contract — NO-DATA semantics)

`query_count_24h` (optional) counts ARIA **query events** in `.claude/aria-telemetry.jsonl` over the trailing 24h, under the repaired ARIA-13 capture contract (v2 schema frozen in `FOUNDATIONS/ARIA_INTEGRATION_DESIGN.md` § 6):

- **v2 lines** (`schemaVersion` present): counted when `event: "query"`; timestamps read from `ts`.
- **v1 legacy lines** (no `schemaVersion`; `{tool, timestamp, latency_ms, success}`): counted as query events; timestamps read from `timestamp`.
- **Heartbeats** (`event: "telemetry-armed"`) are tracked separately, never counted as queries.
- **Probe events** (`probe: true` — synthetic self-test lines) are excluded from all counts.

`telemetry_state` reports the binding NO-DATA semantics (DISC-ARIA-09 / DEC-81):

| Observation | `telemetry_state` | `query_count_24h` |
|---|---|---|
| No telemetry file | `no-data` | omitted (meter never armed — NOT zero) |
| File exists; window has ≥1 heartbeat or ≥1 query | `measured` | emitted (0 is a real measured zero) |
| File exists; window has zero heartbeats AND zero queries | `no-data` | omitted (NOT zero) |

Consumers MUST NOT treat an omitted `query_count_24h` as zero.

## Invocation

```bash
# Unix
bash .claude/oracles/aria-status/run.sh

# Windows
powershell -NoProfile -File .claude/oracles/aria-status/run.ps1
```

Invoked automatically by the session-start hook in parallel with other every-session oracles. The declared `expected_runtime_ms` (500ms) reflects measured cost under Git Bash; the 300ms probe ceiling is the defensive worst case for the HTTP leg.

## Configuration

Optional `.claude/aria.json`:

```json
{
  "endpoint_url": "http://127.0.0.1:14550/aria/health",
  "exposure_mechanism": "tauri-ipc"
}
```

Both fields optional; the oracle uses defaults (`http`, default endpoint URL) if absent.

## Behavior on Edge Cases

- **No surface**: emits `surface_present: false`, all foundation flags `false`, briefing empty (suppressed). Other fields are degraded defaults.
- **Surface present, server unreachable, no aria.json**: surface-but-no-instrumentation briefing.
- **Surface present, server unreachable, aria.json exists**: instrumented-but-unreachable briefing.
- **Server response missing `_meta`**: treated as unreachable (contract violation).
- **Telemetry log corrupt/unparseable**: no parseable in-window events → `telemetry_state: "no-data"`, `query_count_24h` omitted, briefing shows `qph=no-data` (never `0`).
