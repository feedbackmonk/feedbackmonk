# SYNTHESIS — Scrutiny of FeedbackMonk + the GitCellar Integration Seam

**Date**: 2026-07-01 · **Skill**: `/0-uldf-scrutinize --cascade` · **Mode**: analysis-only (no fixes applied; trivial-only inline per Work Discovery Protocol — none taken). **Autonomy**: autopilot.
**Commission**: sole-backend readiness review before GitCellar Phases B/C delete its internal feedback backend and make FeedbackMonk the ONLY home of its feedback, with no fallback. **North-star question for every finding**: *is this good enough to be the sole backend, no safety net, for a privacy-branded product?*
**Evidence**: 10 read-only reviewer children (A1 public API, A2 admin API [2 independent passes], B data layer, C privacy pipeline, D agentic boundary, E frontends, F GitCellar seam, G ops/deploy, H oracle suite, EXT external field scan) + 3 fresh-context Phase-4 mandate critics. Per-child reports are evidence appendices in this directory. Rubric + partition: `00-PARTITION-AND-RUBRIC.md`.

---

## 1. Verdict in one paragraph

FeedbackMonk is, at its core, **better than the field on the things it set out to be good at** — tenant isolation is real and enforced from code (child B verified both scope keys on 60+ queries; the `multi-tenant-isolation-check` oracle is genuine detection-from-code), the JWT verifier is strict and honest (EdDSA-only, alg-checked-before-signature, key-class separation both directions), the P5 agentic approval gate could not be broken on paper, and the widget/admin frontends are disciplined against XSS. **But it is not yet good enough to be a sole, fallback-free backend for a privacy brand**, for three convergent reasons, each found independently by multiple reviewers: (1) **erasure is incomplete** — a "forget me" leaves the person's verbatim/paraphrased text alive in the P5 AI-derived tables and their identity alive in vote/solicitation rows, and the oracle that certifies erasure is structurally blind to exactly those tables; (2) **durability is absent** — attachment bytes are never backed up and default to ephemeral storage, the live deploy has no documented backup/DR, and nothing monitors health; (3) **the public abuse floor does not gate** — the anonymous rate limiter is defeated by rotating a client-controlled cookie, and public attachments are readable by anyone who learns a non-secret short code. The seam itself is well-specified but **its only consumer doesn't actually use most of Phase A**, and the live instance is a version behind the contract. None of this is unrecoverable; all of it should be fixed before GitCellar deletes its fallback.

## 3. Full findings ledger (by severity, then liveness)

Liveness key: **LIVE** = misleads/harms a real user or deployment today; **LATENT** = fires under load, scale, or a specific trigger; **ARCHIVAL** = doc/claim only.

### P0 — wrong / exploitable / existential for the sole-backend privacy brand

- **P0-1 · Erasure leaves the person's text and identity alive (CONV-1).** `me_feedback.rs::delete_my_feedback` → `feedback.rs::delete_for_end_user` is a bare `DELETE FROM feedback … end_user_sub=$` relying on FK cascade; the P5 derived tables have no FK to feedback, and `feedback_solicitations` + `roadmap_votes.voter_id` + `feedback_board_votes.voter_id` are keyed on the JWT `sub` and survive. **Adjudication: the RULE is wrong** — "erasure = row + FK children" is falsified by P5a; the correct rule is "erasure removes all text derived from, and all rows keyed on, the person." **Remediation**: an `erase_end_user(scope, sub)` that, in one txn, deletes all the sub's feedback + solicitation + vote rows and scrubs/re-derives the derived-text fields for affected clusters; add a provenance link (or membership table) so "which derived rows quoted this feedback" is answerable; extend the erasure oracle (P0-4). **Effort M–L.** LIVE.
- **P0-2 · Anonymous rate limiter is non-functional (CONV-3).** `AnonGate::token_hash(ip,cookie,project)` — cookie is client-minted, unsigned, and honored verbatim; rotating it mints unlimited budgets; the Bearer-present path has no limiter at all. **Remediation**: an IP-scoped ceiling (trusted-proxy-derived, P0-3) as the hard limit, cookie kept only for dedup; or HMAC-sign the cookie; add a pre-auth throttle covering the JWT branch too. **Effort M.** LIVE.
- **P0-3 · Public attachments readable/writable by anyone holding a short code (CONV-7).** `attachments.rs` scopes only `open_for_submission(project_id)` + `FB-` code, no submitter binding, no rate limit. Read = PII exposure; write = storage-exhaustion griefing onto another user's feedback; ~10⁹ code space is grindable with no throttle. **Adjudication: the deferral RULE is wrong for a sole backend.** **Remediation**: bind attachment read+write to the submitter identity (JWT `sub` / anon cookie hash) held at submit; add a router-level limiter. **Effort M–L.** LIVE.
- **P0-4 · Attachment bytes never backed up + ephemeral default + no live DR (CONV-8).** `backup.sh`/`restore.sh` cover only Postgres; compose `api` mounts no volume for `./data/attachments`; Railway = ephemeral container FS; `RAILWAY_GITCELLAR.md` has no backup/restore/DR section. A DB restore silently resurrects dangling attachment references. **Remediation**: object-store backup leg (local `tar` / S3 versioning+replication) + matching restore + a DR drill; recommend S3 backend for any non-toy deploy; add a Railway DR section (confirm/enable PITR, scheduled `pg_dump` offsite). **Effort ~1–2 days.** LIVE.
- **P0-5 · CI runs only 1 of 13 oracles; the anti-reward-hacking static layer is absent (CONV-10).** `ci.yml` + both `ci-local.*` invoke only `multi-tenant-isolation-check`. The static probes (the parts tests can't replace — un-allowlisted `body_translated` read, dropped `&TenantScope`, board `approved`-literal→bound-param, dropped `.layer(rate_limit)`) never run in CI. INDEX claims "CI gate" for pii-scrub/widget/tier — false. **Remediation**: one CI job looping every `kind: verification` oracle (cheap static probes on every commit; `--full` behavioral in nightly/pre-release); mirror into `ci-local.sh`; correct the INDEX claims. **Effort ~1–2 hrs.** LIVE (false confidence).

### P1 — gap / staleness / dishonest claim

- **P1-1 · No account recovery / session revocation / password reset / verify-email resend (CONV-4).** Locked-out admin loses the sole backend; leaked 7-day cookie unkillable except by rotating the global session secret (logs out all tenants); a single SMTP failure at signup bricks the account forever (commit-without-rollback + 409 on re-signup + no resend). **Remediation**: password-reset (reuses the email-token machinery), verify-email resend, logout (expiring `Set-Cookie`), and a per-tenant `session_epoch` folded into the HMAC for revocation. **Effort M.** LIVE.
- **P1-2 · No X-Forwarded-For / trusted-proxy client-IP extraction (CONV-5).** **Remediation**: trusted-proxy-aware IP extractor (CIDR/hop-count allowlist — never trust XFF blindly). Prereq for P0-2's IP ceiling. **Effort S–M.** LIVE (in production behind a proxy).
- **P1-3 · Cross-user idempotency collision → silent data loss + short-code leak (CONV-6).** Dedupe PK `(project_id, key)` lacks submitter dimension; also no content-fingerprint (a key reused with different body silently returns the first submission). **Remediation**: include `end_user_sub`/`anon_token_hash` in the idempotency claim PK; store a content hash and 409 on mismatch. **Effort M** (needs migration). LIVE.
- **P1-4 · State↔ledger atomicity is discipline, not structure (CONV-9).** work-orders/status-history expose unpaired advance-state / append-event methods; only moderation combines them. The work-order ledger is the approval-gate oracle's substrate. **Remediation**: a combined `transition_in_executor(state_patch, event)` mirroring `moderate_in_executor`. **Effort M.** LATENT, high blast radius.
- **P1-5 · Global-unique `short_code` + no retry-on-collision → 500s at scale.** 32^6≈1.07e9 global space; ~1% submit-failure at ~10M rows; idempotency retry regenerates a fresh code so it doesn't self-heal. **Remediation**: bounded regenerate-on-conflict loop + per-project uniqueness and/or widen to 8 chars. **Effort S–M.** LATENT, worsens monotonically.
- **P1-6 · Erasure oracle overclaims completeness (CONV-2).** **Remediation**: extend Probe B to enumerate free-text tables reachable from feedback content and assert the erasure path scrubs them; or (interim) narrow the manifest headline to the truth. **Effort (a) 15 min / (b) 3–4 hrs.** LIVE (false confidence).
- **P1-7 · `pii-scrub-audit` never verifies the scrubber is wired into the installed subscriber.** Proves patterns-unchanged + no-competing-subscriber, but not that the scrub layer is in the registry — the exact wiring-removal blind spot the CORS oracle was built to close. **Remediation**: add a probe asserting `install_global_subscriber` applies the scrub layer. **Effort ~1 hr.** LIVE (false confidence).
- **P1-8 · GitCellar consumer does not adopt Phase A** — hard-codes `supports_delete/attachments=false` (no feature-detect), writes `severity` to `external_metadata`, sends no `Idempotency-Key`, ignores `?since=`. Post-cutover the Phase-A goals (first-class severity, dedupe, reply notifications) go unrealized. **Adjudication: consumer-side, but the seam's "additive + capability-advertised = done" framing masked it.** **Remediation** (GitCellar-side, Phase C): wire `GET /capabilities`, add `severity` to `submit`, generate + reuse an `Idempotency-Key`, switch poll to `?since=`+`reply_count`. **Effort M** (other repo). LATENT.
- **P1-9 · Live version-skew hole + false "done" claim.** Live instance v0.2.0, code v0.3.0, A6 redeploy pending; FeedbackMonk `CLAUDE.md` PF-DEPLOY-01 says "No feedbackmonk feature or deploy work remains" (now false — A6 remains) and the contract TL;DR flips every Phase-A row to "built ✅" reading as "live." Nothing programmatically gates B/C on `capabilities` returning the 6 strings. **Remediation**: correct PF-DEPLOY-01; make A6 a checklist that verifies `capabilities` before B/C. **Effort S** + the redeploy (ops). LIVE (doc), LATENT (risk).
- **P1-10 · No queue / retry / graceful-degrade contract; feedback lost when FeedbackMonk or the mint is down.** With the fallback deleted, a down/slow FeedbackMonk (or a down GitCellar mint — P1-11) drops or errors the user's typed feedback; no spool, no documented degrade. **Remediation**: a submit spool + retry on the GitCellar side (leveraging idempotency once wired) and/or an explicit degrade contract + a status signal the consumer polls. **Effort M–L** (mostly consumer-side). LATENT but guaranteed on first outage.
- **P1-11 · 5-minute JWT + server-side mint = re-mint-per-op SPOF.** Every consumer op mints fresh via GitCellar Cloud; if the mint is down while FeedbackMonk is healthy, all authenticated feedback dies. No clock-skew leeway on `exp`, no documented machine-refresh pattern. **Remediation**: document a machine pattern (reuse token until ~30s pre-exp; consider a longer machine-token TTL), add `exp` clock-skew leeway to the verifier. **Effort S** (doc) + S (leeway). LIVE behavior.
- **P1-12 · Operator god-key has no audit trail and no rotation.** `admin_ops.rs::patch_tenant` (tier flips, badge-strip across the whole customer base) writes no audit record, carries no operator identity, supports no rotation/multi-token. **Remediation**: append-only ops-audit ledger; accept a token list for rotation. **Effort M.** LIVE.
- **P1-13 · No monitoring / alerting / error-rate observability (FR-FBR-18 partially unmet).** `/health` exists; nothing watches it; no `/metrics`, no error-rate telemetry. A silently-degrading sole backend pages no one. "No trackers" (about end-users) is being conflated with "no operator telemetry." **Remediation**: external uptime monitor on `/health/ready` (immediate) + a `/metrics` endpoint / self-hosted OpenTelemetry (privacy-preserving). **Effort hours (uptime) / 1–2 days (metrics).** LIVE.
- **P1-14 · A6 redeploy migration-skew hazard.** Railway runs the api binary directly with no migrate init-container; pushing v0.3.0 without the manual migrate step boots new code against a schema missing `00020`/`00021` → submit path errors. **Remediation**: Railway release/deploy command runs `migrate.sh` before traffic; ordered A6 runbook (backup → migrate → verify `/capabilities` → cut over). **Effort ~half day.** LIVE (fires at the A6 moment).
- **P1-15 · Crash-link banner contract-advertised "BUILT" but has no endpoint.** `crash_correlation.rs` resolver exists but is not in `AppState` and no route calls it; contract §5.6 says "feedbackmonk resolves crash_event_id to crash detail." Storage of `crash_event_id` works; the render/resolve half is unwired. **Remediation**: wire `GET …/feedback/{id}/crash-banner` (construct correlator from env) or downgrade §5.6 to "resolver built, endpoint pending." **Effort S–M.** LIVE (contract dishonesty).
- **P1-16 · No user-level "forget me" primitive (data layer).** Only `delete_for_end_user` (single item). A user with 10 items must erase each; identity-keyed rows (solicitation, votes) have no path. Folds into P0-1's remediation. LIVE.

## 4. Cross-cutting consistency (root pass over child outputs)

- **Contract-doc vs code drift (F + read-first)**: `gitcellar-adoption.md` §8 marks admin full-text search (parity gap #3) "MISSING — no search route," but `FR-FBR-PARITY-03` is DONE (`admin_feedback.rs` search endpoint + `00011_feedback_fts.sql`). Contract §8 is stale. **Fix the doc.**
- **"Done"-ness overclaiming is a recurring class, not an instance**: PF-DEPLOY-01 "no deploy work remains" (P1-9), contract TL;DR "built ✅" reading as live (P1-9), §5.6 crash-banner "BUILT" without an endpoint (P1-15), INDEX "CI gate" for un-CI'd oracles (P0-5/P1-6), `feedback-erasure-completeness` "no residual PII" (P1-6), the sanitizer "source-never-leaves" prose (P2-9). **Root cause**: "BUILT" is used to mean "code exists," not "wired, deployed, and verified." This is the honesty-of-claims defect the scrutinize skill exists to surface — the same product that built detection-from-code oracles to prevent self-reported flags is, at the documentation layer, self-reporting "done." Recommend a single honest-status convention (BUILT / WIRED / DEPLOYED / VERIFIED) and demote every claim to its true rung.
- **Severity conflict (C vs B) on the erasure derived-text gap** — C rated it P0, B rated it P1. This is exactly the high-signal cross-child disagreement Phase 4 exists to adjudicate. Resolved to **P0** in §5.
- **Idempotency appears in four children with four lenses** (A1 cross-user collision, B content-fingerprint + unbounded key, F consumer doesn't send it, EXT 2026 best-practice TTL/409) — they compose into one coherent work item (P1-3 + P2-17 + P1-8), not four.
- **The "wiring-removal" blind spot recurs**: the CORS oracle was built to catch `.layer()` removal; yet `pii-scrub-audit` (P1-7) and the missing rate-limit oracle (§6) have the identical blind spot. The pattern is under-generalized — a class of "is the security layer actually in the router/registry?" oracles is warranted.
- **Positive convergence** (external + internal): the JWT/identity architecture (local-signed EdDSA, no shared secret, no auth callback) is *ahead* of the 2026 field (effectively RFC 7523), and the agentic approval gate is one of the stronger structural controls in the space. The gaps are operational-maturity and defense-in-depth, not conceptual weakness.

## 5. Adjudication of the C-vs-B severity conflict (erasure derived-text)

Child C: **P0** (privacy-brand existential). Child B: **P1** (data-model completeness gap). **Root adjudication: P0.** Reasoning: severity here is a function of *consequence under the rubric*, and the rubric's north star is "sole backend, no fallback, privacy brand." A "Plausible for feedback" product that returns 204 to a GDPR erasure request while the person's verbatim words persist in an admin-readable `recommendations.body` is committing the precise failure the brand sells against, with legal exposure (GDPR Art. 17 covers derived copies), no fallback to catch it, and an oracle actively certifying it as complete. B's P1 correctly describes the *mechanism* (a data-model FK gap); C's P0 correctly describes the *consequence*. The fix is B's (provenance + transactional scrub + oracle extension); the priority is C's.

## 8. Phase 4 — mandate-level adversarial verdicts

Three fresh-context critics challenged the load-bearing mandates with license to overturn. **No mandate survived as a bare KEEP** — every one encodes a genuine value but was worded as an absolute the product has outgrown. This is the calibration signal the skill wants: the challenge was not soft.

### 8.1 M1 — Privacy & identity
- **DEC-FBR-04 (JWT `sub` is the only identity) → AMEND.** Keep minimal-identity + no-IdP-callback + short TTL (the differentiator, and the 5-min TTL blunts token-leak). But it is written as a purity absolute that silently implies "erasure is the customer's problem." Amend with an explicit completeness clause: a **customer-mediated per-`sub` erasure+export path** (customer proves control of a `sub`; FeedbackMonk erases by `sub` — no IdP callback, honors the spirit), an **`anon_token_hash`-keyed erasure path**, and **extend the runner-token `jti` denylist to end-user tokens** (the codebase already ships revocation for one token class and withholds it from the identity class — an inexcusable asymmetry). Perverse incentive: as worded, "we can't map the person, by design" becomes a compliance shield.
- **DEC-FBR-02 (no trackers ever; rules out AI in v1) → AMEND.** Keep "no third-party trackers, ever" **verbatim** — no tracker shipped, and processor egress (DeepL, owner-chosen) is categorically different from a tracking pixel. But the "rules out AI in v1" clause is now stale and misleading: the product shipped the agentic loop + sentiment + cloud translation. Replace with a truthful, still-differentiated statement — "privacy-first defaults; no cross-site trackers; AI features are opt-in, self-hostable, egress-gated; any cloud egress is default-off, disclosed, reversible." **Perverse incentive — confirmed serious**: "default-off + retroactive-backfill-on-enable" lets the team bank the privacy brand while shipping the egress surface, with the flip's blast radius (all pending bodies → a third party) hidden behind one toggle. Enabling cloud egress must be disclosed, logged, and forward-only-by-default, not a silent backfill.
- **Erasure invariant (row + FK children) → AMEND the definition; split severity.** FK-cascade is the *verifiable floor*, not the ceiling. Widen the definition to "all text derived from, and all rows keyed on, the person." **Severity split**: **P0** for 1:1 and verbatim-single-source derived text (a `recommendations.body` that quotes one feedback verbatim; and the external DeepL copy once egress is on — see reconciliation note below), **P1** for aggregate multi-source cluster summaries (handle by re-derivation/redaction under a *stated policy*, not blanket deletion). The worst outcome is the green erasure oracle certifying "complete" while identifiable text survives — a passing surface that launders an incomplete guarantee.

### 8.2 M2 — Abuse-resistance & data layer
- **Per-handler `AnonGate` keyed on the unsigned cookie → REPLACE the strategy (keep the component).** The floor must move to a router/middleware layer: a trusted-proxy IP extractor feeding a **class-level per-IP ceiling applied by default to every public route**, cookie-keyed dedup demoted to a refinement on top. Converts security from opt-in-per-handler (which decays as routes multiply — voting/attachments already inherited the gap) to opt-out-by-exception. Generative principle: **cookie entropy must never be the sole gate.**
- **Public attachment scope → REPLACE the *read* mandate; KEEP upload public.** Upload is write-only (no confidentiality risk) — keep public. List/download must bind to the submitter credential (JWT `sub` / `anon_token_hash` matched against the cookie). Generative principle: **a public identifier is never an access token.** "Documented deferral" launders a live PII confidentiality hole into a backlog item that never blocks a gate.
- **Global 6-char `short_code`, no retry → AMEND toward REPLACE.** Not a real tension: a **bounded retry-on-conflict loop** (3 tries → 1% collapses to ~1e-6) is the P0 fix (~10 lines); **per-project uniqueness** is the durable fix. Encode the "negligible at scale" assumption as a runtime check, not a comment that ages into a silent outage.
- **State↔ledger atomicity as discipline → AMEND (downgraded liveness).** Critical correction: the approval gate is **ledger-authoritative and fails closed** — `dispatch`/`is_execution_state` reads `has_approved_event` from the *event table*, not the state column, so a state-ahead-of-ledger drift does **not** open execution. So P1-4 is an **audit-integrity + correctness** concern, *not* a live authz hole (revise its framing accordingly). Still worth promoting to a structural combined-transition primitive now, while there is exactly one caller to migrate (near-zero cost, removes the rot vector before callers multiply).
- **Treadmill test (the critic's sharpest point):** these four are *one class* — "public-route security as a per-handler courtesy; public identifiers as capabilities." Point-patching all four leaves the class intact for the next route (that is literally the history). The remediation is root-cause **only if** it lands as (1) a router-enforced default IP ceiling every new public route inherits, **and** (2) a **Verification Oracle** that fails CI when a public route lacks the ceiling or resolves read-access from a public identifier. Without both, it's three-fixed-today-and-a-fourth-next-phase wearing a remediation label. → This becomes an Arc-1 requirement (§9).

### 8.3 M3 — Seam, contract, ops, ADDs
- **Frozen additive contract → AMEND.** Keep additive + capability-detection (correct for skew + unknown consumers).
