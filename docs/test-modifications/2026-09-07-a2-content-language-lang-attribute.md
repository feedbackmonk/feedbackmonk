## Judge's reason

The only assertion whose value changed is `lang` for `fa` (and, in the admin unit test, its four
provider-less siblings): `"fa"` became `"en"` in nine places across the eight files, and in every one of
them the neighbouring `dir === "rtl"` assertion is retained — and it is newly **added** after the reload in
`public-board-a11y.spec.ts` and in the new admin unit test — so the half of the contract that was supposed
not to move is pinned harder than before. The code diff independently justifies exactly that re-pointing:
`applyDocumentLocale` and `createRoot` now derive `lang` from `contentLanguageOf` / `contentLang`, whose only
input is the frozen C34 table's `deepl` field, which the judge verified is `null` for precisely
`ga, fa, ml, is, si` (catalogs carry `_meta.status: "english-fallback — provider unsupported"`), while
`dirOf` / `dir()` are untouched. The change is upstream of any failure — FR-FBR-34 in
`docs/specs/SPECIFICATION.md` is amended on the owner's word and the plan records the LD escalating A-2
rather than taking it unilaterally — so the test edits would have been correct even if the old
`lang === "fa"` assertions had still been passing; they asserted a spec clause that no longer exists.

`expectSelected` is a genuine distinction, not a dodge: the switcher's value is `i18n.language` (the locale
the visitor is ON), `<html lang>` is now the content language, and both are still asserted exactly (`"fa"`
and `"en"`) rather than one being dropped; the admin unit test pins the same pair
(`document.documentElement.lang === "en"`, `i18n.language === "fa"`). The new tests are real: reverting
`applyDocumentLocale` to `lang = code` turned 5 of 25 admin tests red, and making `contentLang()` return
the raw locale turned one test red in each of `i18n.test.ts` and `ui.test.ts` (166 -> 164 passing); the
provider-covered positives (`de`, `ja`, `pt-BR`) would catch a lazy always-`en` implementation. No input
space was narrowed, no test was skipped, and nothing asserts `deepl === null` itself — the tests speak the
behaviour (`lang`, `dir`, selected locale), not the derivation.

Two notes recorded outside the verdict: the widget "provider covers it" test guards each iteration with
`if (activeLocale() === code)` and `zh-Hant` is not a shipped code, so that one iteration is silently
vacuous (three of four still assert); and `judged_code_diff_sha256` above is `git diff` over the four named
source files, because nothing was staged at judgment time and the working tree carried unrelated in-flight
doc edits from sibling sessions — `finalize.py judge --record` re-verifies only the test hash, which is
over the eight test paths and matches a plain staging of them.
